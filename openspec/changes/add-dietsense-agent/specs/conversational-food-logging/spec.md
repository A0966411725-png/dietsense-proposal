# Spec Delta

## Purpose

讓使用者用自然語言（繁體中文文字）描述飲食後，系統能抽取出食物、份量與餐別並寫入每日日誌；資訊不足時，以最少次數的追問補齊。

## ADDED Requirements

### Requirement: 意圖分類
The system SHALL 把每則使用者訊息分類為 `log_food`、`query_nutrition`、`analyze`、`recommend` 其中之一；無法判斷時 MUST 回問使用者，不得猜測後直接寫入日誌。

#### Scenario: 記錄飲食
- **WHEN** 使用者輸入「午餐吃了一個雞腿便當」
- **THEN** 系統判定意圖為 `log_food`

#### Scenario: 查詢營養
- **WHEN** 使用者輸入「一個雞腿便當大概多少熱量」
- **THEN** 系統判定意圖為 `query_nutrition`，不寫入日誌

#### Scenario: 意圖不明
- **WHEN** 使用者輸入「牛肉麵」且沒有其他上下文
- **THEN** 系統詢問使用者是要記錄這餐，還是查詢營養資訊

### Requirement: 食物實體抽取
The system SHALL 從一則訊息中抽取一個或多個食物項目，每項包含食物名稱、份量描述、加料或修飾詞，以及餐別。

#### Scenario: 複合描述
- **WHEN** 使用者輸入「一碗加蛋的台式牛肉麵，湯喝一半」
- **THEN** 系統抽取出主項「台式牛肉麵（一碗）」、加料「蛋（一顆）」，以及修飾詞「湯攝取 50%」

#### Scenario: 一句多項
- **WHEN** 使用者輸入「早餐吃了蛋餅和一杯無糖豆漿」
- **THEN** 系統抽取出兩個獨立項目，餐別都是早餐

### Requirement: 有上限的澄清追問
The system SHALL 在某項食物的配對信心低於門檻（預設 0.80）時提出一個澄清問題；同一項食物 MUST 最多追問一次，之後改以較寬的熱量區間記錄。

#### Scenario: 信心不足時追問
- **WHEN** 使用者輸入「吃了一份滷味」，且配對信心為 0.55
- **THEN** 系統提出一個問題，詢問主要品項或份量

#### Scenario: 使用者略過追問
- **WHEN** 系統已追問過一次，使用者回答「不知道」
- **THEN** 系統仍記錄該項，並標示為低信心，熱量區間加寬

### Requirement: 記錄可修改
The system SHALL 允許使用者用自然語言更正或刪除當日已記錄的項目，並重新計算當日總量。

#### Scenario: 更正份量
- **WHEN** 使用者說「剛剛的牛肉麵其實是小碗」
- **THEN** 系統更新該筆份量，並回報更新後的熱量區間
