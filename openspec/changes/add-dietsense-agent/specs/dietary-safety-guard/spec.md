# Spec Delta

## Purpose

避免熱量追蹤工具助長過度節食或飲食失調行為；系統在偵測到風險時，以安全提示與轉介取代進一步的限制建議。

## ADDED Requirements

### Requirement: 以完整日或多日資料判斷攝取過低
The system SHALL 只在當日記錄結束（使用者確認或已過預設結算時間）後，或以近 7 日平均判斷攝取是否低於安全下限；不得用尚未結束的當日部分攝取量觸發警示。

#### Scenario: 早餐後不誤判
- **WHEN** 上午 9 點，當日只記錄了一份 350 kcal 的早餐
- **THEN** 系統不發出攝取過低的警示

#### Scenario: 連續多日過低
- **WHEN** 近 7 日平均攝取低於 1,200 kcal
- **THEN** 系統顯示安全提示，並附上專業諮詢資源

### Requirement: 拒絕不安全的限制請求
The system MUST 拒絕產生會讓每日目標低於安全下限的飲食計畫，並說明原因。

#### Scenario: 要求極低熱量計畫
- **WHEN** 使用者要求「幫我排一天 800 卡的菜單」
- **THEN** 系統不產生該菜單，改為說明安全下限並建議諮詢營養師或醫師

### Requirement: 暴食-節食循環提示
The system SHALL 偵測近 7 日內明顯的高攝取日與極低攝取日交替模式，並以非評判的語氣提供提示。

#### Scenario: 偵測到交替模式
- **WHEN** 近 7 日出現 2 次以上「高於 TDEE 50%」緊接「低於 TDEE 50%」的組合
- **THEN** 系統提供溫和提示與支援資源，不給額外的減量建議

### Requirement: 非醫療聲明
The system MUST 在首次使用與每次安全提示時說明本系統不提供醫療診斷。

#### Scenario: 首次使用
- **WHEN** 新使用者完成個人資料設定
- **THEN** 系統顯示非醫療用途聲明
